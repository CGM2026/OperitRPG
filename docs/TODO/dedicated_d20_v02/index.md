# 二十面骰专用应用 0.2.0

用户要求将已经发布的跑团原型精简为专用应用，名称改为“二十面骰”，保留现有战役与手机内更新。此次是对已发布 0.1.0 的兼容升级，固定 applicationId、签名私钥、数据库文件/schema1、核心序列化格式、场景资源字节和备份格式。应用名变化不改变既有模组的 d100 规则。

目标是移除通用 Agent、设备自动化、终端、浏览器、本地推理、语音、虚拟形象、插件市场与其依赖、权限和启动代码。只保留跑团 UI、规则核心、Room 存档、轻量模型配置与 HTTP 请求、SAF 备份和手机更新。发布 APK 要小于 50 MiB，且不含原生 so 或通用工具资产。

## 分工

- rpg_core：轻量模型存储/旧配置兼容、HTTP 协议、Route 模型绑定与协议测试
- rpg_ui：品牌、专用模型设置、主界面设置与更新入口
- release_update：精简 Gradle 与发布 CI、固定签名、APK 体积和资源检查
- 主 Agent：应用入口与权限、移除无用源码资产、旧存档/覆盖升级测试夹具、集成和交付

## 步骤

1. 固定已发布版本兼容约束，保留旧代码在发布标签和 Git 历史中
2. 以 app 和 rpg-core 两个模块构建专用应用
3. 使用旧 model_configs 偏好文件维护模型配置，不丢弃旧配置和未知字段；不支持的旧协议明确提示重新配置
4. 新应用继续打开 rpg-v1.db，验证旧回合、骰点、线索和备份
5. 执行核心/协议/更新测试、正式构建及精简包检查
6. 以相同签名发布 0.2.0 / versionCode 2，验证 0.1.0 的更新清单兼容
7. 尽可能在模拟器通过旧 schema1 测试安装包覆盖升级验证；真实旧 ARM64 APK 与用户手机上的升级保留为独立实机项目

不重新生成签名，不清空用户数据，不重掷已保存骰点，不改写场景资源来适配品牌，不自动切换模型协议或降级到演示。
