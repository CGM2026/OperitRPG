# 0.3 手机交互实施记录

新入口为 `rpg.agent.ui.D20AgentRoute(onOpenLegacy, onModelSettings)`，由统一路由调用。旧版入口传入旧战役 ID；传入 null 进入旧列表，可创建内置模组战役或导入 format1。两种引擎不互相转换。

新首页合并两库标题与更新时间，每次加载 50 条并可继续加载。旧库只读 header，不解码旧 recordJson。新游玩历史按每批 30 条向前读取，打开战役只标记本团中断请求，不启动模型请求。

手机操作路径：

- 设置 → 模组与资料 → 导入模组 / MD / TXT → 查看公开预览 → 确认安装或保存参考资料
- 模组与资料 → 查看示例模组 → 预览 → 确认安装；不会启动时自动安装
- 新建战役 → 模组 → 角色 → 严格采用模组或允许补充细节 → 明确选择模型 → 开始战役
- 模型中的“离线流程演示”是明确的脚本模型选择，真实模型请求失败不会选择它
- 游玩 → 人物、线索、地点、记事、规则；只有公开投影进入 Compose，原始工具结果和 GM 规划不进入界面
- 游玩 → 存档 → 本机模型绑定、完整 format2 导出、模组与资料
- 设置 → 导入长团备份 → 完成文件校验与预览 → 确认安装为独立战役；随后明确绑定本机模型
- 模组与资料 → 选择参考资料 → 选择目标战役 → 添加所选资料；参考资料不成为可执行规则
- 模组与资料 → 选择参考资料和真实模型、调用次数上限 → 明确确认发送 → 编辑草稿 → 校验 → 确认激活

草稿保存在应用私有文件，最多 300 KiB。一次整理的标题和原文合计最多 6000 字；较长资料应先选章节或节选重新导入，不静默截断。预算是上限，当前服务只进行一次明确请求。关闭草稿保留文件，可在资料页重新打开。当前测试版的结构化规则与场景采用 JSON 编辑；格式错误与缺字段保持草稿，不激活。此处仍需要真实模型与人工评估整理质量。

停止请求保留已提交的骰点与结果，继续本轮由用户明确触发。取消行动只用于未提交回合。模型配置被删除或改变时，本团不会换成其他模型；需明确重新绑定。记事更正保留原条目、事件来源与替代关系，不改生命、物品或骰点。

## 独立候选验收

`AgentBlackBoxTest` 不引用 app 实现类，也不直接种入测试战役。它通过 SDK、UiAutomator 与只读 SQLite 检查实际 release 候选。

先单独运行 `newAgentFlowSurvivesActivityRelaunch`，完成示例安装、显式离线模型开团、两次只读工具、一次提交、规则出处、公开人物、记事来源、更正与 Activity 重开。截图和 `agent-ui-result.json` 保存到应用外部文件目录的 `upgrade-review`。

随后在独立 instrumentation 调用中运行 `persistedAgentCampaignSurvivesFreshProcess`；可在两次调用之间显式停止应用。第二段读取第一段留下的期望文件，核对事件原字节、回合 ID 与更正记事，再标记 `freshProcessVerified`。第一段单独完成时不会声称已经做过进程重启验收。

本机没有 Android SDK，未在本机执行 Android 编译与设备测试；最终结果由主线程的 CI 与设备验收记录补齐。真实模型质量验收仍由用户进行。
