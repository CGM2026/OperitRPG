# 01 模组、规则与可导入内容

状态：待实施。由内容/检索开发 Agent 负责；先与存储和运行时确认契约，再写实现。

## 模组格式

新增 `.rpgmodule.zip`，moduleFormatVersion=1。它只包含 UTF-8 JSON、Markdown 和 TXT 数据，不包含脚本、动态库、外部可执行插件或自动请求的远程资源。

标准目录如下，导入器使用固定白名单路径和文件类型。

```text
module/
	manifest.json
	world.json
	rules.json
	sources/
		setting.md
		rules.md
```

manifest 字段：formatVersion、moduleId、version、title、author、description、engineApiVersion、rulesetId、rulesetVersion、各文件大小与 SHA-256。安装后生成由规范化 manifest 和文件摘要确定的 contentHash。hash 用于一致性与版本锁定，不充当作者身份认证。

world 字段：起始角色模板、起始地点、地点与连接、物品、NPC、事实、线索、目标、触发器、预设动作、终止/继续条件和可生成内容策略。所有实体使用稳定且带命名空间的 ID。事实拥有可见范围；秘密不能仅靠文案里的“保密”两个字表示。

rules 字段：注册规则适配器 ID/版本、技能及初始数值、可用资源及边界、时间单位、难度档位、允许的效果类型、规则文档锚点、模组自定规则。规则 ID 必须指向原文锚点，纯机械常量标明为模组自定规则。

每个战役绑定一个基础模组、一个注册规则适配器和明确启用的自定规则版本。资料可追加，但不自动合并另一套可执行规则。模组升级另存新版本；旧战役固定原版本与 hash，引用中的版本不能删除。

## 类型化条件与效果

条件只接受有限组合：位置、资源比较、事实已知/已成立、目标状态、时间比较，以及有限深度的 all/any/not。限制最大深度 8、每条动作最多 64 个条件节点，不允许递归或代码表达式。

效果首批只支持：移动、资源增减、授予/转移物品、公开事实、改变目标状态、设置允许的 NPC 状态、建立知情关系、推进游戏时间。每项都由注册处理器检查类型、边界和权限。未知规则、条件或效果使模组不可激活，并指出具体路径。

适配器接口：validateModule、availableActions、validateProposal、resolve、applyRecordedEvent、validateState。resolve 接收冻结计划和受控骰源；applyRecordedEvent 只应用已经记录的效果，不重新掷骰、不调用模型。事件版本和重放实现必须保留。

首个新适配器为 generic-d100-v1：技能、难度、生命和资源上限可配置，动作不能任意设置骰点。旧 prototype-d100-v1 继续由旧 RainyDock 引擎执行，两者不是原地替换关系。

## 脱离固定动作清单

新引擎包含“预设动作”和“自由行动提案”两条入口，共享同一个结算器。

玩家提出模组未写死的办法时，模型可以提交 investigate、move、negotiate、use_item、wait 或 skill_check 类型，引用当前实体、规则、技能、难度及成功/失败后果。程序验证目标存在、角色可达、资源允许、效果类型受支持以及是否违反模组锁定事实。

有明确规则、后果和用户意图的常规动作直接执行。没有适用规则的玩法只能提交临时裁定，展示可公开的难度与后果，由玩家确认；裁定记录为本团决定，不能伪称原书规则。相互矛盾的规则需要明确选定后再结算。

开团时可选择“严格采用模组”或“允许补充细节”。后者允许模型提议有限的新人物、场景细节和支线，并使用类型化创建命令写入事件；受 modulePolicy 的实体类型、数量和锁定事实约束。新生成内容有 generated 来源，写入后成为可追踪状态，不只存在于聊天文字。主线真相、正式规则和已有历史不允许由模型改写。

这不等于完整开放世界模拟。超出已注册规则能力的战斗、法术或复杂经济系统明确显示尚不支持，不编造可执行结果。

## 手机导入

使用 Android 系统文件选择器选择单个文件，通过 URI 流读取。应用复制经校验的内容到自己的持久存储，战役不依赖原 URI 永久存在。此路径不需要任意目录访问权限，符合 [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files) 的文件选择方式。

导入状态：SELECTED → VALIDATING → PREVIEW → COMMITTING → READY。失败或用户取消不出现可开团的半成品。

校验：规范化路径、拒绝绝对路径/父目录/重复文件/符号链接/未知条目、限制实际解压字节、验证 CRC 与 hash、检查 UTF-8、引用完整性、起始状态、规则兼容和可见范围。初始上限：压缩 20 MiB、展开 50 MiB、2,000 个条目、单文件 5 MiB；以流读取真实字节计数，不能仅信任 ZIP 声明。

预览只展示作者指定的无剧透简介、规则和规模。详细主持内容默认折叠并明确会剧透，普通导入确认不要求用户阅读真相。

普通 MD/TXT 的第一个结果是“参考资料”，可阅读、检索、标记来源。模板化文档若缺少机器可执行字段，也不能直接标为可开团。

“整理为模组”是显式模型任务：先选择要发送的文档、模型与任务预算，再分章节提取到 DRAFT。显示提取结果、来源和缺项；不存在于原文的补充标记为建议。用户可以修改或接受补充，结构校验通过后才能激活。模型整理失败保留草稿与原文，重试由用户发起。不得将文件内的指令当成系统或工具权限。

## 规则检索

采用本地 Room + FTS4，首版不引入向量服务。Room 官方提供 [FTS 实体与 tokenizer 支持](https://developer.android.com/training/data-storage/room/defining-data#fts)；具体实现必须使用仓库锁定的 Room 版本可用 API，不照抄新版文档新增接口。

按标题、段落和规则条目分块，目标每块 300–800 汉字，硬上限 1,200 汉字，保留必要相邻上下文。chunk 保存文档 ID/版本/hash、章节路径、原文偏移、可见范围及可执行规则映射；原文从未经过模型改写。

中文不假设默认 tokenizer 会语义分词。[SQLite unicode61](https://www.sqlite.org/fts3.html#tokenizer)按 Unicode 分隔字符拆词，因此在应用层生成中文双字词元、单字查询索引与规范化英文词，额外索引实体别名、规则标题和同义词表。展示原文，不展示预处理词元。

查询顺序为确定性的组合评分：精确 ruleId/实体与标题命中、FTS 匹配、邻近上下文；每次返回最多 5 个主要片段。没有原文的同义表达需要用评测集调优，不声称词法检索已解决全部语义理解。

查询在 SQL/检索服务内绑定战役固定版本和调用角色权限，过滤后才能取片段、计数和生成摘要。玩家的“查看出处”只能打开获准的内容范围；GM 的隐藏命中数和文档标题也不能泄露给玩家。

返回 RuleEvidence：ruleId、sourceId、sourceHash、anchor、quote、authority 与可访问范围。主持回答必须引用实际返回的证据；程序检查引用 ID/版本/范围，用户可打开原文。证据能核验来源，解释是否符合原文仍需真实模型质量验收。

缺失依据返回 RULE_NOT_FOUND；冲突返回 RULE_CONFLICT。规则检索结果只提供依据，机械计算仍由适配器执行，不把一段自然语言规则直接当代码运行。

## 本模块验收

- 两个无 RainyDock ID、地点及情节的原创外部模组可以导入并游玩；新增第三个合规包不改应用代码
- ZIP 路径攻击、展开超限、悬空引用和未知效果被拒绝；失败不改变已安装模组
- 同 ID 新版本导入后，旧战役的动作定义、规则与事实不变
- 普通文章仅作为资料，模型整理草稿不自动开团或触发游戏动作
- 100 条带金标准的规则问题，其中至少 70 条中文问题；适用问题 Recall@5 目标至少 90%，无依据问题不产生虚构出处
- 检定详情的出处来自冻结的实际规则版本，不由叙述模型生成一个看似合理的链接
