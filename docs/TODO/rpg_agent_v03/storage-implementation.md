# 新引擎存储实现

实现位于 `app/src/main/java/com/ai/assistance/operit/rpg/agent/data/`。新库名称为 `rpg-agent.db`，schema 初版为 1。旧库、旧 DTO、旧 hash 和 format1 服务不在本次存储改动范围内。

`RoomAgentStore` 实现统一 `AgentStore`。战役行只保存当前标量、模块精确版本和 pendingTurnId；回合、事件、模型 attempt、工具结果与旁白分别存储。NPC 身份状态、限定关系维度、目标、事实和知识边使用独立表；物品、章节目标和生成实体分别按实体存储。每次事务只加载当前投影与一个 pending 回合，不加载历史。

`RoomModuleCatalog.install` 在一个事务中保存已验证的不可变模块、原始文件和检索块。64 KiB 原文存储上限按真实 UTF-8 字节计算。原始 world/rules 文件也保留，format2 恢复可以核验 manifest 对原文件的摘要，而不是对重新序列化文本进行错误比对。

FTS4 使用应用生成的中文单字、双字和规范英文词元；查询多字文本采用双字词元。规则检索先在 SQL 绑定战役固定模块版本、追加资料战役与角色可见性，再对最多 200 个已授权候选做确定性评分，返回最多 5 个来源。词法检索的评测集不能代替真实模型对规则的解释验收。

`ReferenceDocumentService.attach` 将参考资料显式关联战役，检索出处 authority 为 reference。它不会注册任何可执行效果。绑定资料与正文进入该战役完整备份。

结算结果产生带事件序号、目标 ID、成功状态和骰点的公开记事。更正新建条目，保存 supersedesId 与独立 correction_event；旧条目保留为 SUPERSEDED，其 FTS 同事务移除，覆盖到该来源的摘要失效。更正不修改正式世界与骰点。correctionHistory 按同战役与逐条权限读取原文链。

每 20 个完成回合建立持久摘要任务。`DerivedTaskService` 只负责显式启动、失败、完成和中断状态，不调用模型。完成摘要时保存来源事件外键，摘要不写入事实表。付费生成入口和任务预算由应用层控制。

format2 使用固定文件名单、实际压缩/展开计数、逐文件 SHA-256 和单 JSONL 行 1 MiB 限制。导出先在数据库一致性事务内将分页历史复制到临时文件，释放数据库锁后流式 ZIP 打包。导入先暂存和验证模块原文、版本、事件顺序及重放投影，再在新库单事务创建新 ID 的独立战役。正文、事件、回合、旁白、记事与更正、摘要及其来源、任务、主张和绑定资料均包含；不含 FTS 缓存、模型 attempt、工具调用原输出或凭据。当前模型绑定清空，冻结的历史计划配置指纹保留以保持其原始 hash 含义。

已新增 JVM 分词/UTF-8 分块与 ZIP 限额测试、Room 磁盘重开/事务/10,000 历史分页备份/权限矩阵测试，以及 100 条公开规则金标样本，其中 80 条为中文。Android 测试位于 `app/src/androidTest`，样本位于其 `assets/rpg-agent`。本机没有 Android SDK，这些新增测试仍需 CI 实际编译执行；尚无设备耗时或内存结果，未作真实模型质量验收。

## 当前测试版的实际限制

已提交事件产生 EVENT 记事；完成且无结算结果的问答、澄清产生 PUBLIC CONVERSATION 记事。对话记事保存有限的玩家原话与主持回应，并明确标记“对话记录，不代表世界状态”，sourceTurnId 指向保留完整原文的精确回合。长文本的检索副本会截断，原回合不截断。format2 保留并重映射这个来源，更正继续保留来源和类别。尚未自动把对话中的承诺拆成可验证的结构化义务，也不会把对话升格为正式事实。

NPC 的身份、位置、状态、关系、目标、计划时点和知识边能够持久化；目前没有离场 NPC 目标到期后的自主调度入口。它们只随合法结算效果变化。

摘要只有持久队列、来源、失效和任务状态服务。该服务尚未接入 UI 启用设置及摘要模型调用，没有自动生成有效章节摘要；持久任务存在不等于摘要能力已经完成。

claim 表与备份的 claims.jsonl 已就绪，但尚未接入模型候选事实的审核、确认和激活业务。正式事实与主张的分表不能当作完整候选事实工作流已经可用。
