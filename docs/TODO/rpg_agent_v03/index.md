# 二十面骰 0.3：可持续跑团的专用 Agent

本轮交付开发方案，尚未实施或发布 0.3。目标是让用户在手机导入模组，使用有出处的规则，通过自然语言持续行动；主持能够查询过去发生的事情，维护 NPC 的位置、关系、目标和知情范围，并在中断后准确继续。0.2 的旧战役与手机更新继续可用。

## 当前结构与必须解决的问题

0.2 的 ScenarioDefinition、PlanParser、TurnCoordinator、RoomGameStore 和备份校验都绑定 RainyDock。把 JSON 文件替换掉不能得到新模组。CampaignRecord 将全部回合与事件存入一个 recordJson，每轮解码、校验、重写整个战役；UI 初始化还会读取所有战役。这些路径不适合长团。

当前 ContextBuilder 只取最近八个完成回合，NPC 知识来自固定场景函数。模型接口明确拒绝供应商原生工具输出。已有可靠部分是显式阶段、计划确认、检定事务、请求去重、叙述恢复、备份校验和同证书更新。

## 本版完成标准

- 手机导入两个不同的外部数据模组，无须改 Kotlin 或重新打包 APK，即可分别新建和游玩
- 新模组具有不同地图、人物、情节和资源，运行于本版注册的原创百分骰规则适配器；不会假称已经实现 CoC 或 D&D
- 支持预设动作，也支持在所选规则与世界约束内提出新的调查、移动、交涉、使用物品、等待和技能检定
- 规则回答与检定详情能打开实际采用的本地出处；查不到依据时明确说明，临时裁定需确认并留档
- 跨章节、跨退出重启查询过去的事实、承诺、关系及未完成目标；记忆纠错可追溯
- NPC 有持续状态及各自的知识/信念，按游戏时间变化，不跟随手机墙上时间偷偷推进
- 模型能多轮调用获授权的专用查询工具，再提交一次可校验的行动方案；一轮最多一次世界结算
- 10,000 回合样本的分页、检索、保存和备份通过性能验收，并有真实模型的跨会话长对话记录
- 0.1/0.2 战役、进行中回合、format1 备份与手机内更新经过覆盖升级验证

“长期”指持续状态、受预算控制的上下文、可追溯记忆和可恢复执行，不承诺无限上下文或模型永不遗忘。

## 恢复、重做与继续保留

恢复能力但不搬回旧通用框架：专用工具调度、多步查询、资料检索、可扩展的动作注册、长期记忆。它们在小型专用运行时内实现。

重做：通用模组契约、规则适配器、长团数据存储、上下文装配、NPC 状态/知情模型、新备份格式和新版回合协调器。旧代码作为兼容引擎继续运行，新引擎通过独立契约实现。

继续保留：Compose 界面体系、黑体与低饱和配色、28dp 留白、四类文本模型连接、本机模型配置、现有签名、更新清单及 GitHub 通道。

本版不恢复：终端、跨 App 点击、任意脚本、通用浏览器、插件市场、本机大模型、语音及虚拟形象。本版不引入向量数据库、强制云服务、后台无人值守行动或多人同步。

## 用户可见范围

首页仍以战役为中心。设置新增“模组与资料”，新建战役可选择模组和规则；游玩页新增“记事”，人物、线索、地点沿用现有入口。检定卡展示可点击的规则出处，进度只显示“查阅规则、核对记录、结算行动、保存记录”等实际阶段。

结构化模组包可直接校验后开团。普通 Markdown/TXT 可以立即作为可检索资料导入；用户可主动选择模型整理为模组草稿，经过缺项检查与预览确认后才能开团。原文中的规则描述不会自动成为可执行代码。扫描 PDF、OCR、DOCX 和任意文本一键全自动成团不纳入本版完成标准。

旧战役标为沿用原版规则，照常继续；不会在升级时自动变成新引擎战役。旧战役直接获得新版全部玩法不属于本版承诺。以后若提供转换，只能创建独立副本并另行验收，原档保留。
