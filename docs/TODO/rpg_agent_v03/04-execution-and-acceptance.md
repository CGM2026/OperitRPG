# 04 开发分工、交互与验收

状态：待实施。以下是交给开发 Agent 的任务顺序，不表示已有功能完成。沿用用户要求：下属 Agent 使用 GPT 6.1 太阳模型，中等推理度。

## 第一步交付契约，不并发改同一个核心文件

主 Agent 先固定 CampaignRef、ModuleManifest、RuleEvidence、AgentStep、ActionProposal、CommittedResult、WorldEvent、RoleContext、Fact/Claim、KnowledgeEdge、MemoryItem 和 BackupManifestV2 的版本化结构及合法/非法样本。

维护 invariants 文档：旧 DTO/hash 不变、模型无直接写库权限、先授权再检索、一次提交、来源可追溯、版本固定、未知规则明确拒绝。契约变更需同步所有样本和受影响任务，不靠字段默认值掩盖不一致。

开发分工最多三个下属同时工作，主 Agent 负责接口裁决、共享 Gradle/路由、合并与最终发布。

- Agent A，运行时与规则：rpg-agent/contract、engine、rules、tools；先做规则契约和无模型可运行路径，再接 Agent 循环
- Agent B，资料与长期状态：模组导入、规则/记忆检索、新 Room 存储、NPC 与备份；按依赖顺序交付，核心事务先于摘要
- Agent C，手机交互与验收工具：新页面、公开投影 UI adapter、升级夹具和端到端验收；用冻结 fixture 接口先做 UI，不能另造一套数据结构

Agent B 工作较多，A 完成规则后承接 NPC/记忆纯逻辑；B 始终拥有新数据库 schema 和 DAO，避免多人同时修改。主 Agent 独占 settings.gradle.kts、app/build.gradle.kts、版本号、总路由和发布 workflow。每个任务结束提交实际检查结果、未覆盖范围与后续依赖，不写笼统“测试通过”。

## 里程碑与任务包

M0：兼容基线和合同。主 Agent + A。

- 保存 0.2 已签名 APK、发布证书指纹、原 schema、资源和序列化/hash 固定样本
- 补齐旧 PLANNING、NEEDS_CONFIRMATION、PREPARED、RESOLVED、NARRATING 的数据夹具，以及旧 format1 备份
- 建立上述 v1 新协议样本和 module-format schema 文档，事件定义包括重放所需的实际效果
- 验收：旧文件 diff 清晰，新协议正反例不依赖 Android，所有后续任务使用同一份版本

M1：双引擎入口与新存储。B + 主 Agent；依赖 M0。

- 新建 rpg-agent 模块与 rpg-agent.db；完成表、唯一约束、事务、分页 header/turn DAO
- 实现 CampaignRef、两套 UI adapter 与选中状态升级；旧库 DAO 仅增加轻量查询
- 用固定 ActionProposal 运行新引擎基本结算、事件重放和中断恢复
- 验收：同一首页能打开旧战役和新引擎样本；旧存档字节/hash 与规则保持原状；新库单次回合不扫描全历史

M2：数据模组与通用规则。A + B；依赖 M0/M1。

- 完成模组包验证、暂存预览、事务激活、版本固定、RuleAdapter 注册和 generic-d100-v1
- 完成有限条件/效果、预设与自由行动提案校验、模组可生成内容策略
- 制作两个原创外部测试模组，例如“驿站失踪案”和“边境巡护”；每个至少 6 个地点、12 个 NPC、3 个章节目标，不能是码头内容换名
- 验收：换包即可换世界，不重编 APK；地图、目标、时间和人物由包决定，不出现硬编码 12 步结束或 RainyDock 专名

M3：规则检索、事实、NPC 和记忆。B，A 承接纯逻辑；依赖 M1/M2。

- 建立原文分块/中文词元/FTS、可见范围与版本过滤、RuleEvidence 和出处打开
- 完成规范化事实/主张/知情边、NPC 关系目标、游戏时钟、带来源记事、纠错链和索引同步
- 完成 ContextAssembler、分页历史检索和有来源范围的章节摘要任务
- 验收：第 1 章承诺可在第 3 章被检索；NPC 不共享玩家全部记忆；修正后原文可追溯且旧错误不再作为有效事实召回

M4：真实 Agent 循环。A + 主 Agent；依赖 M2/M3。

- 拆出 TextModelPort，保留旧 adapter 行为；新建 AgentStep 严格解析、工具注册、角色权限、预算和持久状态机
- 把查询结果重新送给模型，让模型选择后续查询或提交提案；接入临时裁定确认、一次结算、公开叙述
- 完成取消、断线、配置变化、迟到响应、预算耗尽和无依据处理
- 验收：使用脚本模型精确验证工具轨迹，再使用真实模型完成跨资料/跨回合任务；工具运行与世界提交都有可检查记录

M5：手机完整流程与备份。C + B；UI 可从 M1 起按接口并行，整体验收依赖 M4。

- 模组与资料、新建选择、规则出处、记事纠错、NPC 公共投影、明确阶段进度
- MD/TXT 资料导入；显式模型整理草稿、缺项修改与确认激活，不把普通文档冒充可执行包
- format2 流式导入导出、完整依赖内容、模型重绑定；保留 format1 路径
- 验收：纯手机完成导入、开团、跨会话继续、查询历史、纠错、导出及空白安装恢复

M6：长团、升级与发行。主 Agent + C；依赖 M0–M5。

- 运行下述自动化和真实模型验收，修复实际问题
- 按相同签名生成候选，使用下载的实际候选覆盖升级，不以重编出的另一个 APK 代替
- 通过后发布同一 APK、校验清单、变更说明、验收报告与实拍图；手机检查更新可发现新版
- 验收：验收文件 hash 与公开资产一致，0.1/0.2 到新版路径保留旧战役，新 format2 在空白设备恢复成功

M0–M2 可作为内部迭代，但不能把它们单独标为“长期跑团 Agent 已完成”。正式 0.3 需要五个能力全部连成一条可验收流程。

## 最小手机交互

保持战役首页，不新增复杂底部导航或开发者控制台。

“设置 → 模组与资料 → 导入”调用系统选文件，展示无剧透预览、版本和具体错误。普通文档显示“参考资料”；只有契约完整并通过校验的内容显示“可用于开团”。

“新建战役”增加模组选择、角色模板、严格/允许补充细节及模型选择。选项默认值说明实际影响，旧存档不因这些选项变化而改写。

游玩页保留人物/线索/地点，增加“记事”；记事按事件、承诺、目标、玩家备注等实际内容显示。每条能打开来源，更正时显示原内容与新内容，不展示内部 hash、工具参数或检索分数。

检定详情展示实际使用的规则出处和裁定。自定规则标明“本团裁定”，没有依据明确说明。NPC 私有状态不做成玩家可随手点开的后台面板。

进度对应实际阶段，完成后可展开公开依据。工具读取不反复弹确认；复合行动、临时裁定、导入激活和记事更正保持明确确认。黑体、低饱和配色、28dp 留白延续。

## 自动化验收门槛

兼容：原 74 项测试保持通过，任何替换必须说明原来覆盖了什么、由哪项新测试继续覆盖，不能为通过而删除约束。旧五种中断阶段与完整/取消战役升级后可继续，尤其 NEEDS_CONFIRMATION/PREPARED 的旧 hash 不变化。

导入：合法包可开团；非法路径、重复 ID、未知规则、循环条件、超大文件、版本/hash 冲突和缺失引用被拒绝；导入中断后没有可见半模组。新版本不影响旧战役。

规则：100 条金标准问题，适用问题 Recall@5 至少 90%；无依据问题不伪造引文；所有返回的出处 ID/版本可验证。准确率是本地评测目标，不是对任意规则书的保证。

记忆：10,000 回合跨章节测试，包含至少 200 个预埋事实/承诺/更正问题；确定性结构查询结果 100% 正确，检索问题 Recall@5 目标至少 90%。摘要错误不能改变正式状态，更正后重建索引结果一致。

隔离：跨战役、玩家/GM/NPC/阵营的权限矩阵与至少 1,000 个组合测试，不允许任何未授权源记录进入对应上下文或出处。真实模型另测语义剧透，不能用权限测试代替输出质量测试。

执行：并发发送、重复提交、重复工具 ID、过期 revision、取消和迟到响应；在骰点/事件/NPC/事实/结果写入边界注入失败，重开结果仍是零次或一次提交，不能出现半笔效果或重复掷骰。

备份：旧 format1 往返；format2 在空白安装恢复正文、依赖、事件、记忆与来源；未知引擎/事件版本或损坏数据不激活；中断回合导出限制明确，模型凭据不进入任何备份。

性能初始目标：固定并记录 Android 测试设备，在 10,000 回合、100 个 NPC、20,000 个资料块下，首页首屏 P95 小于 1 秒、本地记忆/规则检索 P95 小于 500 ms、单轮本地事务 P95 小于 200 ms，峰值应用内存目标小于 200 MiB。测量不包含云端推理时间；若未达标先定位，不把目标写成已实现。

应用体积目标小于 10 MiB，硬上限沿用 50 MiB。除已核实的 AndroidX 小型绘图依赖，不重新引入大型通用原生库。

## 真实模型与人工验收

用用户明确选定并配置的模型和调用预算进行，不从其他项目取 Key。两份不同模组各至少 100 次交互，跨 5 次退出/重开、3 个章节，覆盖过去承诺、指代/别名、规则争议、NPC 谣言、知识隔离、自由行动和叙述中断。

每个关键规则引用检查是否真的支持解释；每次状态变化能追到合法事件；越权写入、重复结算、跨战役数据混用为零容忍发布阻断项。评测集中的关键约定事实不得与正式状态矛盾，未通过问题修复后重测相关场景。

新增至少 60 条针对未发现秘密、伪装管理员指令和错误记忆的真实模型对抗输入。对模型偶然猜中真相、隐含剧透及表达质量记录具体结果；未做真实模型验收时只能交付内部测试版，不把 Mock 测试当作长团质量证明。

发布测试包括 Android API 26 与 36 的基础兼容，以及真实 0.2 已签名小包的 x86_64 覆盖升级。0.1 ARM64 历史包保持对应架构实机/设备测试范围，不能把合成夹具说成历史 APK 实测。手机厂商安装器的权限返回需要实机验收。
