# 06 导出、分叉与完结

## 入口

- 首页长按战役菜单增加：「导出」（二级：备份、战报）、「标记完结」/「取消完结」。完结的战役在列表第二行显示"已完结"。
- 已完结的战役，导出二级菜单多一项「主持复盘」。点它先弹确认框：「复盘包含全部隐藏设定与幕后事件，导出后无法撤回剧透。」确认后才导出。
- 对话页"⋯"→「章节」页每个已到达章节旁增加「从这里另开一局」。

所有导出都走系统文件选择器（`ActivityResultContracts.CreateDocument`），文件名默认 `<战役标题>-<yyyyMMdd>.<扩展名>`。

## 1. 备份（`.d20save`）

- 沿用现有 `AgentBackupService` 的导出/导入格式与校验，扩展名改为 `.d20save`，导入时只接受该扩展名的文件内容格式校验（按内容校验，不按扩展名猜）。
- 备份额外包含首页元数据：分组名、置顶、隐藏、完结、显示标题、手动头像。导入时分组按名字匹配，没有就新建。
- 导入入口：首页 `+` 菜单增加「导入备份」。

## 2. 战报（`.md`）

只含玩家可见内容（PUBLIC），结构：

```
# <战役标题>
模组：<模组标题> <版本>　角色：<角色名>　导出时间：<yyyy-MM-dd HH:mm>

## 第 1 章 · <章节标题>
> <章节摘要（如有）>

**你**：<玩家输入>
<叙述正文>
`<骰子行，与对话页小标签同格式>`
……
```

没有章节的模组不分章。生成逻辑写成纯函数 `CampaignReport.markdown(...)`，可单元测试。

## 3. 主持复盘（`.md`，仅完结后）

- 战役元数据完结标记存在 `campaign_meta.finished INTEGER`（数据库仍是版本 1，直接改实体；v0.5 未发布，不需要迁移）。
- 内容：全部事实（含隐藏）及其可见性与玩家是否已知；全部已触发与已取消的计划事件（标题与游戏时间）；NPC 最终状态；章节推进时间点。生成逻辑写成纯函数 `CampaignRecap.markdown(...)`，可单元测试。

## 4. 从章节另开一局

- `AgentBackupService` 增加 `fork(campaignId, uptoSeq, newTitle)`：复制战役到第 `uptoSeq` 号事件（含）为止，重放得到新战役；回合、叙述、记忆只复制来源事件序号不超过 `uptoSeq` 的部分；新战役标题默认「<原标题>（第 N 章起）」，新 campaign_meta 继承分组与头像，未完结。
- 用某章的 `ChapterMark` 所在事件序号作为 `uptoSeq`。

## 验收

CI 绿；单元测试：战报不含任何非 PUBLIC 内容（构造含 GM 事实的战役断言）；复盘包含 GM 事实；fork 后新战役的世界状态与原战役在该事件后的状态一致（用 rpg-agent 的重放在 JVM 测试里比对）。
