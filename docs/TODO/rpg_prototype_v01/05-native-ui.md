# 原生跑团界面

原有应用没有跑团界面。本次增加战役列表、新建、游玩、人物/线索/地点抽屉和战役设置，通过 RpgUiController 对接持久化和核心，不读取隐藏剧情数据。

页面采用 28dp 横向留白、系统黑体、暖白底色和莫兰迪配色。模型选择复用已有配置；演示模型必须明确标记。进入或恢复页面只读取数据，不自动发起模型请求。

范围为 rpg/ui、Screen.Rpg 和主侧栏注册。系统文件选择器承接存档导入导出，导入在预览确认后写入。进行中禁止切换模型和导出，恢复操作区分未结算与已结算叙述。

已实现战役列表、新建与模型选择、游玩与检定折叠、确认首步、错误重试/取消、人物背包、线索详情与来源跳转、已知地点、设置、规则和终局。输入草稿使用 rememberSaveable 按战役隔离；超过 2000 字提示修改。抽屉支持滚动和返回层级，游戏数据只来自 RpgUiState。

导航同时注册 ScreenRouteRegistry 和 OperitApp 的原生 navItems 清单。更新按钮复用独立更新模块。RpgUiController 由 integration 层实现，UI 不持有密钥或核心隐藏状态。

静态检查 git diff --check 通过；构建检查由集成执行者统一进行。

补充审查：Screen 的全仓 when 分派已有通用 Content 分支，NavItem 没有穷尽枚举分派。终局后保留规则/回顾输入；禁止新行动由核心约束。canAct 表示没有进行中回合，最终结算但叙述中断时仍禁止切模型及导出。地点在终局后只能查看。

小屏检查：列表与历史采用 LazyColumn，新建/设置/规则及三个抽屉纵向滚动；输入区使用权重留给历史，最多三行，跟随 IME padding；键盘展开时输入最多两行，收起地点状态与抽屉快捷行，为阅读上下文留出高度。导入预览及长错误文本可滚动。原 AppContent 已消费系统 inset，子层 imePadding 不重复叠加。

新增 Android Compose 仪器测试 RpgScreenTest，覆盖终局规则输入、320×480 小屏待恢复时资料可读/发送禁用，以及长模型列表滚动至存档操作。测试会把真实渲染 PNG 保存至应用专用 external-files/rpg-ui-review。当前无设备/模拟器，未执行仪器测试或宣称截图验收；不引入额外截图库，也不阻塞 APK 构建。
